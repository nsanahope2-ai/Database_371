## Problem Summary

A clinic offers each doctor four daily appointment slots: **`09:00`**, **`10:00`**, **`11:00`**, and **`12:00`**. Two non-cancelled appointments (`BOOKED` or `ATTENDED`) must never occupy the same doctor, date, and slot, whereas a `CANCELLED` slot may be rebooked. All database objects are isolated inside schema `q04_clinic`.

---

## (a) Database Schema and Seed Data [6 Marks]

### Design & Constraints
- **`patients`**: `patient_id` (PK), `full_name`, plus private patient attributes (`phone`, `date_of_birth`) used to verify column-level data minimization in Part (e).
- **`doctors`**: `doctor_id` (PK), `full_name`.
- **`appointments`**: `appointment_id` (PK), `patient_id` (FK), `doctor_id` (FK), `appointment_day` (`DATE`), `slot_time` (`TIME`), and `status`, enforcing:
  - `slot_time IN (TIME '09:00', TIME '10:00', TIME '11:00', TIME '12:00')` (`chk_appointments_valid_slot`)
  - `status IN ('BOOKED', 'ATTENDED', 'CANCELLED')` (`chk_appointments_valid_status`)
- **`clinic_summary`**: `summary_date` (PK), `booked_count`, `attended_count`, `cancelled_count`.
- **Seed Data**: 3 patients, 3 doctors, and 6 appointments across `CURRENT_DATE - 1` and `CURRENT_DATE`, including a `CANCELLED` appointment and an `ATTENDED` appointment on the same doctor/day/slot (`Doctor 1`, `CURRENT_DATE - 1`, `10:00`) to demonstrate legal slot reuse after cancellation.

```sql
DROP SCHEMA IF EXISTS q04_clinic CASCADE;
CREATE SCHEMA q04_clinic;
SET search_path TO q04_clinic, public;

CREATE TABLE patients (
    patient_id    INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name     VARCHAR(150) NOT NULL CHECK (LENGTH(TRIM(full_name)) > 0),
    phone         VARCHAR(30)  NULL,
    date_of_birth DATE         NULL
);

CREATE TABLE doctors (
    doctor_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name VARCHAR(150) NOT NULL CHECK (LENGTH(TRIM(full_name)) > 0)
);

CREATE TABLE appointments (
    appointment_id  INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    patient_id      INT NOT NULL REFERENCES patients(patient_id) ON DELETE RESTRICT,
    doctor_id       INT NOT NULL REFERENCES doctors(doctor_id) ON DELETE RESTRICT,
    appointment_day DATE NOT NULL,
    slot_time       TIME NOT NULL,
    status          VARCHAR(20) NOT NULL,
    CONSTRAINT chk_appointments_valid_slot
        CHECK (slot_time IN (TIME '09:00', TIME '10:00', TIME '11:00', TIME '12:00')),
    CONSTRAINT chk_appointments_valid_status
        CHECK (status IN ('BOOKED', 'ATTENDED', 'CANCELLED'))
);

CREATE TABLE clinic_summary (
    summary_date    DATE PRIMARY KEY,
    booked_count    INTEGER NOT NULL CHECK (booked_count >= 0),
    attended_count  INTEGER NOT NULL CHECK (attended_count >= 0),
    cancelled_count INTEGER NOT NULL CHECK (cancelled_count >= 0)
);
```

## (b) Doctor Daily Load Function: `fn_daily_load` [6 Marks]

### Logic
- Rejects `NULL` inputs and raises an exception when `p_doctor_id` does not exist in `doctors`.
- Counts non-cancelled (`status <> 'CANCELLED'`) appointments for `p_doctor_id` on `p_day`, naturally returning `0` when the doctor has no active bookings on that date.

```sql
CREATE OR REPLACE FUNCTION fn_daily_load(
    p_doctor_id INT,
    p_day       DATE
)
RETURNS INTEGER
LANGUAGE plpgsql
AS $$
DECLARE
    v_load INTEGER;
BEGIN
    IF p_doctor_id IS NULL THEN
        RAISE EXCEPTION 'Doctor ID (p_doctor_id) cannot be NULL.';
    END IF;

    IF p_day IS NULL THEN
        RAISE EXCEPTION 'Appointment day (p_day) cannot be NULL.';
    END IF;

    IF NOT EXISTS (SELECT 1 FROM doctors WHERE doctor_id = p_doctor_id) THEN
        RAISE EXCEPTION 'Doctor ID % does not exist.', p_doctor_id;
    END IF;

    SELECT COUNT(*)::INTEGER
      INTO v_load
      FROM appointments
     WHERE doctor_id = p_doctor_id
       AND appointment_day = p_day
       AND status <> 'CANCELLED';

    RETURN v_load;
END;
$$;
```

## (c) Appointment Booking Procedure: `pr_book_appointment` [8 Marks]

### Logic
- Rejects `NULL` arguments, unknown `p_patient_id`, unknown `p_doctor_id`, past dates (`p_day < CURRENT_DATE`), and unsupported slot times outside `{09:00, 10:00, 11:00, 12:00}`.
- Inserts a new row with `status = 'BOOKED'`.

```sql
CREATE OR REPLACE PROCEDURE pr_book_appointment(
    p_patient_id INT,
    p_doctor_id  INT,
    p_day        DATE,
    p_slot       TIME
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_patient_id IS NULL OR p_doctor_id IS NULL OR p_day IS NULL OR p_slot IS NULL THEN
        RAISE EXCEPTION 'All booking parameters (patient, doctor, day, slot) must be non-NULL.';
    END IF;

    IF NOT EXISTS (SELECT 1 FROM patients WHERE patient_id = p_patient_id) THEN
        RAISE EXCEPTION 'Patient ID % does not exist.', p_patient_id;
    END IF;

    IF NOT EXISTS (SELECT 1 FROM doctors WHERE doctor_id = p_doctor_id) THEN
        RAISE EXCEPTION 'Doctor ID % does not exist.', p_doctor_id;
    END IF;

    IF p_day < CURRENT_DATE THEN
        RAISE EXCEPTION 'Cannot book appointment in the past (% < %).', p_day, CURRENT_DATE;
    END IF;

    IF p_slot NOT IN (TIME '09:00', TIME '10:00', TIME '11:00', TIME '12:00') THEN
        RAISE EXCEPTION 'Unsupported slot %. Allowed clinic slots are 09:00, 10:00, 11:00, and 12:00.', p_slot;
    END IF;

    INSERT INTO appointments (patient_id, doctor_id, appointment_day, slot_time, status)
    VALUES (p_patient_id, p_doctor_id, p_day, p_slot, 'BOOKED');
END;
$$;
```

```text
NOTICE:  [PASS] Unsupported slot rejected by pr_book_appointment: Unsupported slot 08:30:00. Allowed clinic slots are 09:00, 10:00, 11:00, and 12:00.
NOTICE:  [PASS] Unknown patient rejected by pr_book_appointment: Patient ID 999 does not exist.
```

## (d) Slot-Clash Prevention Trigger [8 Marks]

### Logic
- Fires `BEFORE INSERT OR UPDATE` for each row on `appointments`.
- Immediately permits rows where `NEW.status = 'CANCELLED'`.
- Locks the parent `doctors` row (`FOR UPDATE`) to serialize concurrent booking transactions for the same doctor and searches for any existing `status <> 'CANCELLED'` row matching `(NEW.doctor_id, NEW.appointment_day, NEW.slot_time)`.
- Explicitly excludes the row being modified during `UPDATE` via `AND (TG_OP = 'INSERT' OR a.appointment_id <> NEW.appointment_id)`, allowing status transitions such as `BOOKED -> ATTENDED` while blocking `UPDATE`s that move an appointment into another occupied slot.

```sql
CREATE OR REPLACE FUNCTION fn_trg_prevent_slot_clash()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
DECLARE
    v_conflict_id INT;
BEGIN
    IF NEW.status = 'CANCELLED' THEN
        RETURN NEW;
    END IF;

    PERFORM 1
      FROM doctors
     WHERE doctor_id = NEW.doctor_id
       FOR UPDATE;

    SELECT a.appointment_id
      INTO v_conflict_id
      FROM appointments a
     WHERE a.doctor_id = NEW.doctor_id
       AND a.appointment_day = NEW.appointment_day
       AND a.slot_time = NEW.slot_time
       AND a.status <> 'CANCELLED'
       AND (TG_OP = 'INSERT' OR a.appointment_id <> NEW.appointment_id)
     LIMIT 1;

    IF v_conflict_id IS NOT NULL THEN
        RAISE EXCEPTION
            'Slot clash: Doctor % already has a non-cancelled appointment (ID %) on % at %.',
            NEW.doctor_id, v_conflict_id, NEW.appointment_day, NEW.slot_time;
    END IF;

    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_appointments_prevent_clash
BEFORE INSERT OR UPDATE ON appointments
FOR EACH ROW
EXECUTE FUNCTION fn_trg_prevent_slot_clash();
```

### Verification Notices
- Booking `Patient 3` with `Doctor 3` at `12:00` today succeeds (`Appointment 7`).
- Updating `Appointment 7` from `BOOKED` to `ATTENDED` and back to `BOOKED` succeeds without self-clashing.
- Both duplicate `INSERT` and colliding `UPDATE` are rejected:

```text

NOTICE:  [PASS] UPDATE slot clash rejected by trigger: Slot clash: Doctor 2 already has a non-cancelled appointment (ID 5) on 2026-11-24 at 10:00:00.
```

## (e) Privacy-Preserving View: `v_today_appointments` [5 Marks]

### Data Minimization
Exposes **only** `patient_name`, `doctor_name`, and `slot_time` for `CURRENT_DATE` rows with `status = 'BOOKED'`. Internal keys (`patient_id`, `doctor_id`, `appointment_id`), clinical status metadata, `phone`, and `date_of_birth` are strictly withheld.

```sql
CREATE OR REPLACE VIEW v_today_appointments AS
SELECT p.full_name AS patient_name,
       d.full_name AS doctor_name,
       a.slot_time
  FROM appointments a
  JOIN patients p ON p.patient_id = a.patient_id
  JOIN doctors d  ON d.doctor_id  = a.doctor_id
 WHERE a.appointment_day = CURRENT_DATE
   AND a.status = 'BOOKED';
```

## (f) Non-Unique Composite Index and `EXPLAIN` Plan [5 Marks]

### Index Justification
1. **Why Non-Unique:** A single doctor can legitimately hold up to **four active appointments** (`09:00`, `10:00`, `11:00`, `12:00`) plus any number of `CANCELLED` rows on the same `appointment_day`. A `UNIQUE` index on `(appointment_day, doctor_id)` would restrict each doctor to at most one row per day and break clinic scheduling.
2. **Why `(appointment_day, doctor_id)` Column Order:**
   - Directly satisfies composite equality searches (`WHERE appointment_day = ? AND doctor_id = ?`) used by `fn_daily_load`, doctor daily schedules, and clash checks.
   - By the B-tree **leftmost-prefix rule**, placing `appointment_day` first also accelerates date-level queries (`v_today_appointments` and `pr_refresh_clinic_summary(p_day)`) without needing a separate single-column index on `appointment_day`.

```sql
CREATE INDEX idx_appointments_day_doctor
    ON appointments (appointment_day, doctor_id);

ANALYZE appointments;

SELECT appointment_id, patient_id, doctor_id, appointment_day, slot_time, status
  FROM appointments
 WHERE appointment_day = CURRENT_DATE
   AND doctor_id = 1
 ORDER BY slot_time;
```

## (g) Daily Clinic Summary Job: `pr_refresh_clinic_summary` [6 Marks]

### Logic & Idempotency
- Computes `BOOKED`, `ATTENDED`, and `CANCELLED` counts in a single pass using SQL `COUNT(*) FILTER (WHERE status = ...)` for `p_day` (returning `0` for each status if the clinic had no appointments on `p_day`).
- Uses `INSERT ... ON CONFLICT (summary_date) DO UPDATE` so reruns replace that date's summary cleanly.

```sql
CREATE OR REPLACE PROCEDURE pr_refresh_clinic_summary(p_day DATE)
LANGUAGE plpgsql
AS $$
DECLARE
    v_booked    INTEGER;
    v_attended  INTEGER;
    v_cancelled INTEGER;
BEGIN
    IF p_day IS NULL THEN
        RAISE EXCEPTION 'Summary date (p_day) cannot be NULL.';
    END IF;

    SELECT COUNT(*) FILTER (WHERE status = 'BOOKED')::INTEGER,
           COUNT(*) FILTER (WHERE status = 'ATTENDED')::INTEGER,
           COUNT(*) FILTER (WHERE status = 'CANCELLED')::INTEGER
      INTO v_booked, v_attended, v_cancelled
      FROM appointments
     WHERE appointment_day = p_day;

    INSERT INTO clinic_summary (summary_date, booked_count, attended_count, cancelled_count)
    VALUES (p_day, v_booked, v_attended, v_cancelled)
    ON CONFLICT (summary_date) DO UPDATE
        SET booked_count    = EXCLUDED.booked_count,
            attended_count  = EXCLUDED.attended_count,
            cancelled_count = EXCLUDED.cancelled_count;
END;
$$;
```

### Daily `01:00` Schedule (`pg_cron`) & Local Windows PostgreSQL 18.6 Note
On Linux/cloud PostgreSQL instances with `pg_cron` enabled, the job runs daily at **01:00** (`0 1 * * *`) summarizing the previous day (`CURRENT_DATE - 1`):

```sql
SELECT cron.schedule(
    'q04_daily_clinic_summary',
    '0 1 * * *',
    'CALL q04_clinic.pr_refresh_clinic_summary(CURRENT_DATE - 1);'
);
```

Because `pg_cron` and `pgAgent` are not bundled with the local Windows PostgreSQL 18.6 installation, `solution.sql` guards `cron.schedule(...)` in an extension-check `DO` block and directly executes `pr_refresh_clinic_summary(CURRENT_DATE - 1)` **twice** (plus `CURRENT_DATE`) to verify idempotent replacement:

```text

--------------+--------------+----------------+-----------------

 2026-11-24   |            3 |              1 |               0
(2 rows)
```
