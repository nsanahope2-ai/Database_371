## Problem Summary

A transport company tracks vehicle trips and flags maintenance alerts whenever a vehicle has travelled **at least `5,000` kilometres** since its last service (`(current_odometer - last_service_odometer) >= 5000`). Every new trip must begin at the vehicle's exact `current_odometer`, advance `current_odometer` once inside a `BEFORE INSERT` trigger on `trips` (never inside the trip-recording procedure), expose due vehicles via a view, index per-vehicle date-range trip lookups, and refresh `service_alerts` every Monday at `06:00` (including deleting alerts once serviced).

## Part-by-Part Solution & Verification

### (a) Database Schema and Seed Data `[6 marks]`

Three normalized tables are created in `q08_fleet`:

```sql
CREATE TABLE vehicles (
    vehicle_id            INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    registration          VARCHAR(20) NOT NULL UNIQUE CHECK (btrim(registration) <> ''),
    current_odometer      INTEGER NOT NULL CHECK (current_odometer >= 0),
    last_service_odometer INTEGER NOT NULL CHECK (last_service_odometer >= 0),
    CONSTRAINT chk_vehicles_service_le_current
        CHECK (last_service_odometer <= current_odometer)
);

CREATE TABLE trips (
    trip_id        INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    vehicle_id     INTEGER NOT NULL REFERENCES vehicles(vehicle_id) ON DELETE RESTRICT,
    trip_on        DATE NOT NULL,
    start_odometer INTEGER NOT NULL CHECK (start_odometer >= 0),
    end_odometer   INTEGER NOT NULL CHECK (end_odometer > start_odometer)
);

CREATE TABLE service_alerts (
    vehicle_id       INTEGER PRIMARY KEY REFERENCES vehicles(vehicle_id) ON DELETE CASCADE,
    km_since_service INTEGER NOT NULL CHECK (km_since_service >= 5000),
    flagged_on       DATE NOT NULL DEFAULT CURRENT_DATE
);
```

### (b) Function `fn_service_due` `[6 marks]`

```sql
CREATE OR REPLACE FUNCTION fn_service_due(p_vehicle_id INTEGER)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
    v_current      INTEGER;
    v_last_service INTEGER;
BEGIN
    IF p_vehicle_id IS NULL THEN
        RAISE EXCEPTION 'Vehicle ID must not be NULL.';
    END IF;

    SELECT current_odometer, last_service_odometer
    INTO v_current, v_last_service
    FROM vehicles
    WHERE vehicle_id = p_vehicle_id;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Vehicle ID % does not exist.', p_vehicle_id;
    END IF;

    RETURN (v_current - v_last_service) >= 5000;
END;
$$;
```

**Live Verification Output:**
- Returns `t` for `BAA 4102 ZM` (`5,650 km`), `t` for `BAC 8830 ZM` (`5,000 km`), and `f` for `BAD 2295 ZM` (`2,450 km`).
- `fn_service_due(9999)` and `fn_service_due(NULL)` both raise clear exceptions (`[PASS]` verified in `DO` block).

### (c) Trip Recording Procedure `pr_record_trip` `[8 marks]`

```sql
CREATE OR REPLACE PROCEDURE pr_record_trip(
    p_vehicle_id INTEGER,
    p_trip_on    DATE,
    p_start      INTEGER,
    p_end        INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_vehicle_id IS NULL THEN
        RAISE EXCEPTION 'Vehicle ID must not be NULL.';
    END IF;

    IF p_trip_on IS NULL OR p_start IS NULL OR p_end IS NULL THEN
        RAISE EXCEPTION 'Trip date, start_odometer, and end_odometer must all be non-null.';
    END IF;

    IF p_start < 0 THEN
        RAISE EXCEPTION 'Trip start_odometer (%) must be non-negative.', p_start;
    END IF;

    IF p_end <= p_start THEN
        RAISE EXCEPTION 'Trip end_odometer (%) must be strictly greater than start_odometer (%).',
            p_end, p_start;
    END IF;

    IF NOT EXISTS (SELECT 1 FROM vehicles WHERE vehicle_id = p_vehicle_id) THEN
        RAISE EXCEPTION 'Vehicle ID % does not exist.', p_vehicle_id;
    END IF;

    INSERT INTO trips (vehicle_id, trip_on, start_odometer, end_odometer)
    VALUES (p_vehicle_id, p_trip_on, p_start, p_end);
END;
$$;
```

- Validates parameters and vehicle existence, then performs `INSERT INTO trips` **only** — `vehicles.current_odometer` is never updated in `pr_record_trip`, avoiding double odometer advancement.

### (d) Odometer Continuity Trigger `trg_trips_before_insert` `[8 marks]`

```sql
CREATE OR REPLACE FUNCTION fn_trg_trips_before_insert()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
DECLARE
    v_current_odo INTEGER;
BEGIN
    IF NEW.vehicle_id IS NULL OR NEW.trip_on IS NULL
       OR NEW.start_odometer IS NULL OR NEW.end_odometer IS NULL THEN
        RAISE EXCEPTION 'Trip vehicle_id, trip_on, start_odometer, and end_odometer cannot be NULL.';
    END IF;

    IF NEW.start_odometer < 0 OR NEW.end_odometer <= NEW.start_odometer THEN
        RAISE EXCEPTION 'Invalid trip mileage (start=%, end=%): require 0 <= start < end.',
            NEW.start_odometer, NEW.end_odometer;
    END IF;

    SELECT current_odometer
    INTO v_current_odo
    FROM vehicles
    WHERE vehicle_id = NEW.vehicle_id
    FOR UPDATE;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Vehicle ID % does not exist.', NEW.vehicle_id;
    END IF;

    IF NEW.start_odometer <> v_current_odo THEN
        RAISE EXCEPTION 'Odometer continuity violation for vehicle %: trip start_odometer (%) does not match current_odometer (%).',
            NEW.vehicle_id, NEW.start_odometer, v_current_odo;
    END IF;

    UPDATE vehicles
    SET current_odometer = NEW.end_odometer
    WHERE vehicle_id = NEW.vehicle_id;

    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_trips_before_insert
BEFORE INSERT ON trips
FOR EACH ROW
EXECUTE FUNCTION fn_trg_trips_before_insert();
```

- Acquires a row-level lock (`FOR UPDATE`) on `vehicles` to serialize concurrent trip inserts for the same vehicle.
- Verifies `NEW.start_odometer = current_odometer` and `NEW.end_odometer > NEW.start_odometer`, then updates `vehicles.current_odometer = NEW.end_odometer` **exactly once**.
- Verified in `DO` block: mismatched `start_odometer` and `end_odometer <= start_odometer` via **both** `CALL pr_record_trip(...)` and direct `INSERT INTO trips (...)` were rejected, leaving `trips` count (`6`) and Vehicle 1's `current_odometer` (`45650`) completely unchanged.

### (f) Composite Index `idx_trips_vehicle_trip_on` `[5 marks]`

```sql
CREATE INDEX idx_trips_vehicle_trip_on
ON trips (vehicle_id, trip_on);
```

**Justification:**
1. **Equality Prefix + Range Suffix Rule:** Fleet dispatch and audit queries look up trips for a specific vehicle (`WHERE vehicle_id = ?`) across a date window (`AND trip_on BETWEEN ? AND ?`). Putting the equality column `vehicle_id` first narrows the B-tree search to a single vehicle's contiguous leaf entries, and placing `trip_on` second allows an immediate range scan within that slice.
2. **Sort Elimination:** Because `trip_on` is stored in ascending order within each `vehicle_id`, `ORDER BY trip_on` is satisfied directly from the index scan without an external `Sort` operator.
3. **Foreign Key Support:** Leading on `vehicle_id` also indexes the `trips.vehicle_id -> vehicles.vehicle_id` foreign key for joins and parent-row checks.

**Actual PostgreSQL 18.6 `EXPLAIN` Plan (`enable_seqscan = off` on the 6-row seed table):**
```text

-----------------------------------------------------------------------------------------------------
 Index Scan using idx_trips_vehicle_trip_on on trips
   Index Cond: ((vehicle_id = 1) AND (trip_on >= (CURRENT_DATE - 30)) AND (trip_on <= CURRENT_DATE))
(2 rows)
```

### (g) Scheduled Job `pr_refresh_service_alerts` `[6 marks]`

```sql
CREATE OR REPLACE PROCEDURE pr_refresh_service_alerts()
LANGUAGE plpgsql
AS $$
BEGIN
    -- 1. Remove alerts for vehicles whose service has brought them below 5,000 km
    DELETE FROM service_alerts sa
    WHERE NOT EXISTS (
        SELECT 1
        FROM vehicles v
        WHERE v.vehicle_id = sa.vehicle_id
          AND (v.current_odometer - v.last_service_odometer) >= 5000
    );

    -- 2. Upsert one alert for every vehicle currently due (>= 5,000 km)
    INSERT INTO service_alerts (vehicle_id, km_since_service, flagged_on)
    SELECT
        v.vehicle_id,
        (v.current_odometer - v.last_service_odometer) AS km_since_service,
        CURRENT_DATE
    FROM vehicles v
    WHERE (v.current_odometer - v.last_service_odometer) >= 5000
    ON CONFLICT (vehicle_id) DO UPDATE
        SET km_since_service = EXCLUDED.km_since_service,
            flagged_on       = EXCLUDED.flagged_on;
END;
$$;
```

**Live Lifecycle Verification:**
1. **Run 1 (`CALL pr_refresh_service_alerts()`):** Populates `service_alerts` for Vehicle 1 (`BAA 4102 ZM`, `5650 km`) and Vehicle 2 (`BAC 8830 ZM`, `5000 km`).
2. **Run 2 (immediate rerun):** Remains 2 rows with zero duplicate-key errors.
3. **Run 3 (after Vehicle 1 travels `45650 -> 46000` and Vehicle 2 is serviced with `last_service_odometer = current_odometer`):**
   - Vehicle 1's alert updates in place to `6000 km`.
   - Vehicle 2's alert is **automatically removed** from `service_alerts` (`0 km < 5000 km`).
